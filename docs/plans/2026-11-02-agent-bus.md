# Agent Bus — agent-to-agent communication for `/agent/mcp`

Status: P0 + P1 implemented
Scope: `~/code/raft-source` (Raft) used as the reference model; single-user local
hub, no multi-tenant surfaces copied.

## Problem

`/agent/mcp` is a **star topology**. The orchestrator holds every `agent_id` and
every session; a subagent can only be prompted by whoever spawned it. Three
consequences:

1. **No peer channel.** Agent A cannot ask agent B anything; A's question must
   travel through the orchestrator's context window and back. Findings are
   copied by value, so the orchestrator pays tokens for traffic it is not part of.
2. **Pull-only, in-memory delivery.** `Exhub.MCP.Agent.Store` keeps
   `event_queues` / `waiters` in one GenServer. A restart loses everything, and
   fan-out needs one long-poll per agent (`agent_prompt_events` × N).
3. **No participant identity.** `agent_id` names a process, not a participant:
   no description, no capabilities, no status vocabulary, no memory. There is
   nothing to address when a process is gone.

## What Raft does (the parts worth copying)

| Raft primitive | Mechanism | What it buys |
| --- | --- | --- |
| Identity ≠ session | agent = identity + workspace + `MEMORY.md`; session = model context | messages are addressed to a participant |
| Shared surfaces | channel / DM / thread; visibility inherited, **delivery by membership**, **attention by @mention** (two axes) | peers see each other's work without a relay |
| Durable inbox | unread list + read position, content-free wake hints | no loss on restart, no busy polling |
| Task = lock | claim before first tool call; `todo→in_progress→in_review→done/closed` | no duplicated work |
| Evidence handoff | changed / where / evidence / uncertainty / next | handoffs need no re-discovery |
| Status vocabulary | `raft-agent-status.v1` + short detail | "online" ≠ "can reply" |
| Idempotency keys | replay same result; reuse with a different body → 409 | retries don't double-spend |

Not copied: servers/channels ACL matrix, scopes, Socket.IO, reminders, cloud
runtimes. ExHub is a local single-user hub — rooms are flat and unauthenticated.

## Design

### P0 — identity (`Exhub.Agent.Registry`)

A participant record, file-backed:

```
~/.exhub/agents/<id>/agent.json
~/.exhub/agents/<id>/MEMORY.md     # seeded once, owned by the agent
```

```
id, name, description, capabilities[], kind ("acp" | "sagents" | "external"),
status, detail, created_at, updated_at, last_seen_at
```

- `status` is validated against a closed vocabulary (`starting | idle | working |
  blocked | waiting_input | done | error | offline`), `detail` ≤ 200 chars — the
  Raft rule, so a status line can be rendered without interpretation.
- ETS-backed read path, GenServer write path, `:agent_home` overridable for tests.
- `agent_set_status` writes **both** the ACP store and the registry, so the two
  views cannot disagree.

### P1 — the bus (`Exhub.Agent.Bus`)

A separate supervised process, not an extension of `Agent.Store` (that one
already long-polls per session; mixing messaging in would add head-of-line
blocking and make restart recovery harder).

Streams:

- `agent:<id>` — direct messages to one participant
- `room:<name>` — a shared log; any member reads and posts (no ACLs)

Message:

```
%{id, stream, seq, from, to, kind, body, reply_to, idempotency_key, inserted_at}
kind :: "ask" | "tell" | "reply" | "handoff"
```

Durability + delivery semantics:

- every message is appended to `<bus_home>/<stream>.jsonl` before it is ACKed;
- `seq` is per-stream and monotonic, so `since_seq` replay is exact;
- cursors are per `(agent, stream)`, server-side and persisted; `agent_inbox`
  drains unread and advances them, `peek: true` leaves them alone;
- delivery is **at-least-once** — a crash between write and cursor persist
  re-delivers, which is the correct failure direction for agent messages;
- last 500 messages per stream are kept in memory for history reads.

Tools (all accept `as`, falling back to the `x-exhub-agent-id` header, which
`/agent-bus/mcp?as=<id>` injects):

| Tool | Purpose |
| --- | --- |
| `agent_register` | create/update my participant record (idempotent upsert) |
| `agent_identity` | my record + home + memory path |
| `agent_list` | participants with status, unread and running flag |
| `agent_send` | `ask` / `tell` / `handoff` / `reply` to one participant |
| `agent_inbox` | drain my unread (long-poll with `wait_ms`) |
| `agent_await` | block until named agents are idle/done/error or reply |
| `agent_room_open` / `agent_post` / `agent_room_history` | shared log |
| `agent_bus_status` | one synthesis snapshot (Raft coordinator-synthesis) |

### Capability scoping

`/agent-bus/mcp` mounts **only** the bus tools. A subagent given this endpoint
cannot spawn agents, grant permissions, or shut anything down — the analogue of
Raft's `mcp` scope. `agent_new_session(..., expose_bus: true)` injects
`{"name": "exhub-bus", "uri": "http://127.0.0.1:<port>/agent-bus/mcp?as=<agent_id>"}`.

Note: HTTP MCP support varies by runtime (Gemini requires a non-empty
`mcpServers`, Codex supports HTTP, some adapters only speak stdio). `mcp_servers`
is passed through verbatim so a caller can supply a stdio bridge instead.
